# よいのこ — Flutterフロントエンド

善行の記録とキャラクター育成を組み合わせたiOS向けアプリ。作業ブランチは `front`。Flutter 3.41.1 / Dart 3.11.0 で確認しています。

## デザイン

ユーザー提供のターコイズと白い雲のイメージをもとに、背景・入力欄・カード・ボタン・下部ナビを統一しています。ステータスは読みやすさを優先して淡いミント背景と白いカードを使い、文字と属性色を濃くしています。配色は `lib/core/theme.dart`、雲の装飾は `lib/widgets/cloud_background.dart` で管理します。現在の画面例は `docs/cloud-theme/` にあります。

## キャラクターのアニメーション

ポノと第一進化6種はRive、ミケルナは全身のコマアニメーション、最終進化は既存画像の移動・回転・伸縮で表示します。Riveの第一進化モデルは簡易版です。

ミケルナは全身画44枚を使い、横・手前・奥への歩行、停止、振り向き、瞬き、タップの表情変化、おやすみに対応します。左右反転の途中で幅を潰さず、足を着いて正面や後ろの中間画を通ります。移動速度に応じて歩くコマの周期を変え、向きを変える間は部屋での移動を待機します。素材と再生成手順は [ミケルナの素材ガイド](artwork/mikeluna/README.md) にあります。設定の「キャラクターの動きをみる」でミケルナを選ぶと、4方向と「おさんぽ」を育成記録を変えずに確認できます。

ホームでは上下左右・斜めの8方向から移動先を選び、名前とセリフがキャラクターに追従します。ミケルナの歩行画は進行方向に近い4方向から選びます。タップ反応中・低HP時は移動を止め、投稿画面を開いても位置・大きさを変えず背景で動き続けます。図鑑の展示は静止し、OSの「動きを減らす」設定にも対応します。

## 起動

このディレクトリで実行します。

```sh
flutter pub get
flutter run --dart-define=APP_MODE=demo
```

Webで画面を確認する場合（製品の主対象はiOS）:

```sh
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 5173 --dart-define=APP_MODE=demo
```

実APIにつなぐ場合は、バックエンド担当から受け取った `/api` までのURLを指定します。

```sh
flutter run --dart-define=APP_MODE=api --dart-define=API_BASE_URL=https://YOUR_HOST/api
```

`YOUR_HOST` は置き換えが必要です。接続先やトークンをソースへ書き込まないでください。リリース版はHTTPS必須、接続先未設定なら設定エラーを表示します。明示的な `APP_MODE=demo` はリリース用プレビューでも使用できます。実機ビルドではXcodeでチーム・Bundle ID・署名を設定してください。

## 9画面と操作

1. 初回登録：名前の入力・検証・登録。
2. ホーム：HP、XP、今日の善行、キャラクターのタップ反応。
3. 善行投稿：500文字、二重送信防止、失敗時の再送、閉じる際の入力破棄確認。
4. 投稿結果：褒め言葉と実際に獲得したXP・属性ポイント・HPを表示。
5. うちのこ：7属性、レベル、進化までのXP、善行へのリンク。
6. 歴代図鑑：ガラスケースと木の台座、世代ごとの表示、追加読み込み。
7. 育成記録：各世代の情報・善行履歴、追加読み込み・再試行。
8. おやすみ／世代交代：記録を保持し、許可された日時から新しい子を迎える。
9. 設定：プレイヤー名の変更、退会の確認。引き継ぎ設定は仕様どおり準備中。

下部タブは「ほーむ・うちのこ・とうこう・ずかん・せってい」。アプリに戻るとサーバーの最新状態を再取得します。通信失敗時は既存データを残し、再試行を案内します。

## デモと本番の境界

デモは端末内保存です。分類・褒め言葉はキーワードによる固定処理で、AIではありません。XPは1件10・日本時間の1日上限50。進化条件は現在のバックエンド既定値と同じ100/300XPです。第一進化はそれまでの属性、第二進化は第一進化後に積んだ属性で分岐し、同点は最後の投稿時刻・完全同時刻はカテゴリ定義順で決めます。XP上限後の属性ポイントは0です。HPの経時減少は再現しません。第二進化の当日は育成中を保ち、翌日から次世代を迎えられます。

APIモードは提供された2026-10-24 API仕様v2に対応したアダプターを実装しています。進化の画像IDは最新mainのバックエンド実装とも対応を確認しています。実サーバーのURLは未提供のため、通信を模擬した契約テストまでの確認です。HP・XP・進化条件・褒め言葉・翌日判定はサーバーの値を正として表示します。進化閾値が未取得の場合、推測値は表示しません。

トークンは `flutter_secure_storage` へ接続先ごとに保存します。登録後に保存だけ失敗した場合、同じレスポンスのトークン保存を再試行します（プロセス終了をまたぐ回復はサーバー側の仕組みが必要）。投稿の同じ内容の再送には同じUUIDを使い、内容を変更したらUUIDを更新します。401でトークンを自動削除したり、新規ゲストを勝手に作ったりしません。

## 種族名と進化演出

57種の確定した種族名をホーム・うちのこ・図鑑・育成記録へ反映しています。個体の保存IDや進化の判定は変えず、表示名をカタログで管理します。第一進化の表示サイズはホーム幅の60%、第二進化は70%。投稿結果はキャラクターの上に配置しています。

進化した投稿の保存が成功し、投稿画面を閉じたあとに全画面演出を表示します。第一進化5.5秒、第二進化6.5秒で、浮遊→属性色の光→白いシルエット→進化後の姿→種族名の順に表示。「これからもよろしく」でホームへ戻ります。右上でスキップでき、OSの動きを減らす設定では即座に結果を表示します。アプリが背面へ移ると演出と音を止めます。演出は保存データを変更せず、再起動や同じ投稿の再送で繰り返しません。

短いオリジナルのチャイムを同梱し、左上でON/OFFを変更できます。設定は端末に保存し、iOSの消音設定に従います。再生できない環境でも画面は進行します。ブラウザーの自動再生制限で音が出ない場合は音のアイコンをタップして再試行できます。デモモードでは設定の「第一進化の演出をみる」「第二進化の演出をみる」から育成記録を変えずに確認できます。

演出プレビューは第一進化7種・第二進化49種からランダムに選びます。各段階の全種類を一巡するまで重複せず、第二進化は同じ系統の第一進化から変化します。候補の順番はアプリ起動中だけ保持し、保存データには書き込みません。

## ホームのセリフ

57キャラそれぞれに10種類の固定セリフを用意し、ホーム表示時とキャラのタップ時にランダムで選びます。直前と同じ言葉は続けません。文章は `lib/data/character_speech.dart` で編集できます。対応するキャラの選び方・表示処理・確認方法は [セリフの編集ガイド](docs/character-speech.md) を参照してください。

## キャラごとの褒め口調

善行投稿後の褒め言葉は、57キャラの性格・一人称・話し方に合わせます。本番はバックエンドのAIが具体的な投稿内容から生成し、デモは同じ性格設定の文型を使います。設定の正本は `backend/src/config/character-personalities.json` です。編集後、リポジトリの一番上で `python3 tools/generate_character_personalities.py` を実行するとデモにも反映されます。[編集手順と57キャラの一覧](docs/character-praise.md) を参照してください。

## キャラクター描画の差し替え

ポノと第一進化6体のRiveは同梱済みです。ミケルナの全身コマ再生と合わせて、画面からは共通のCharacterViewで利用します。差し替え口は `lib/widgets/character_view.dart` の `CharacterRendererScope` / `CharacterRenderer` です。

カスタムレンダラーにはCompanion、animate、CharacterMotion（idle / happy / tapped / lowEnergy / sleeping）を渡します。標準レンダラーはモデルの読み込み、破棄、静止画へのフォールバック、動きを減らす設定を扱います。図鑑の `animate: false` やTickerModeによる停止にも対応してください。Rive標準入力はmodeとlookXです。

画像IDの対応表は `lib/data/character_catalog.dart`。`base_01`、`stage1_<category>` の7種、`stage2_<first>_<second>` の49種を提供画像に対応づけています。未知のIDは初期画像にフォールバックします。光＝思いやり、草＝環境保全、風＝感謝、炎＝勇気、水＝協力、鉱石＝誠実、月＝セルフケアです。PNGで進化を表示し、Riveモデルが届いたら描画を差し替えます。

進化の画像IDとデモの条件は最新mainのバックエンド実装も確認して揃えています。実サーバーとの結合確認は接続先の提供後に必要です。

`flutter test test/evolution_test.dart test/evolution_flow_test.dart test/evolution_api_test.dart` で57画像ID・7×7の分岐・同点判定・再起動後の保存・翌日の世代交代を確認できます。通し操作では「草のシカ→月のシカ」をホーム・ステータス・図鑑・詳細に表示し、`build/qa/evolution-*.png` を出力します。旧デモの保存データも進化段階や善行を消さずに画像へ対応づけます。素材の由来と切り抜き処理は `assets/README.md` を参照してください。
